# מאה בקליק

אתר שיעורים פרטיים: דף בית, הזמנת שיעור, לוח בקרה למורה, ופורטל אישי לכל
תלמיד/ה והוריו, כולל תבניות משחקי תרגול. תהליך Node אחד — SvelteKit עם
`adapter-node` — מגיש גם את האתר וגם את ה-API; הנתונים חיים ב-SQLite וכמה
קובצי JSON, בלי שירותי ענן חיצוניים מלבד Google Calendar/Gmail ו-Claude
(ליצירת שיעורים).

## מבנה

| | |
|---|---|
| `src/routes/` | דפים ונקודות API — קובץ `+page.svelte`/`+server.ts` אחד לכל מסלול. `src/routes/app/*` (דשבורד, פורטל, משחקים) דורש התחברות; `src/routes/booking`, `src/routes/portal`, `src/routes/login` ציבוריים |
| `src/routes/api/` | נקודות ה-API (הזמנה, זמינות, פורטל, תוצאות משחק, יצירת שיעורים...) |
| `src/lib/server/` | לוגיקת שרת בלבד — אימות מורה (`auth.ts`), גישת משפחה (`family-auth.ts`, `family.ts`, `join.ts`), SQLite (`db.ts`, `entities.ts`, `migrations/`), תשלומים (`payments.ts`), נתיבי קבצים (`content.ts`, `paths.ts`), חתימת URL (`urls.ts`), צנרת יצירת שיעורים (`lesson/`) |
| `src/lib/plans.ts` | סולם השיעורים — משך, שם בעברית ומחיר במקום אחד. טופס ההזמנה, מייל האישור ומסך הסיכום נטענים ממנו |
| `src/lib/games/` | מנוע המשחקים המשותף (`engine.ts`) שמריץ את 12 תבניות המשחק כרכיבי Svelte |
| `src/lib/components/` | פריסה ורכיבים משותפים |
| `games/registry.json` | תצורה סטטית: אילו תבניות משחק קיימות, מה הצורה של קובץ הנתונים שלהן, ואיזו תבנית מתאימה לאיזו מטרת למידה — נקרא בזמן ריצה, לא נבנה לתוך התמונה בנפרד |
| `seed/games-data/` | קובצי דוגמה/הדגמה לנתוני משחקים, נטענים ל-`DATA_DIR/games-data` באותה שיטה |
| `static/` | נכסים סטטיים (תמונות וכו') שמועתקים לתוך ה-build |
| `server/` | תצורת פריסה עצמית: Dockerfile-adjacent scripts, Caddyfile, גיבוי, ותיעוד ה-VPS המלא — [`server/README.md`](server/README.md) |
| `scripts/` | כלי שורת פקודה למפתחת (למשל `prepare-lesson.mjs` ליצירת שיעור מהטרמינל) |
| `tests/` | `tests/unit` — מבחני יחידה; `tests/characterization` — מריץ את ה-build המלא (`build/index.js`) ומאמת מול ההתנהגות המתועדת |
| `mea-beclick-kb/` | מסמך הדרישות והחזון הוא `PRODUCT.md` בשורש הריפו; בכספת נשארות רק תיקיות `students/` ו-`pricing/` המקומיות, שאינן במעקב git |

## כניסה לדף האישי

אין סיסמאות למשפחות. הזהות היא **כתובת המייל של החשבון**, וההגעה לדף היא
דרך קישור חתום שנשלח לאותה כתובת.

- **הורה / תלמיד בוגר** — בהזמנה נשלח קישור למייל, והוא גם מוצג ישירות במסך
  הסיכום עם כפתור העתקה ושליחה בוואטסאפ. הקישור תקף לשבועיים ופותח סשן
  לחצי שנה. אפשר לבקש קישור חדש מ-`/portal` בלי מעורבות של המורה.
- **תלמיד/ה** — ההורה מייצר מהפורטל שלו קישור אישי לילד/ה (סשן מצומצם: רק
  הלוח שלו/ה, בלי תשלומים ובלי אחים), או מוסר **קוד צירוף** בן 6 תווים,
  חד-פעמי, תקף לשבוע — למכשיר בלי וואטסאפ.
- **תלמיד בוגר שמשלם לעצמו** — `accounts.is_self`. אין פיצול הורה/תלמיד,
  אין שלב שיתוף: זהות אחת, קישור אחד.

חשבון אחד יכול להחזיק כמה תלמידים (אחים), והזמנה חוזרת מאותה כתובת מייל
מתחברת אוטומטית לאותו חשבון. `src/lib/server/family-auth.ts` מחזיק את
החתימות והתפוגה; `src/lib/server/family.ts` מחזיק את שאלת ההרשאה עצמה
(אילו תלמידים המבקר רשאי לפתוח).

פרטי פריסה עצמית, Docker Compose, אימות/הרשאות מלאים והליך ה-Cutover
מ-Express: [`server/README.md`](server/README.md).

## הרצה מקומית

```bash
npm install
ADMIN_PASSWORD=... SESSION_SECRET=... npm run dev
```

משתני סביבה נוספים (יומן גוגל, Gmail) אופציונליים —
בלעדיהם התכונות שתלויות בהם נסוגות בעדינות (למשל: הזמנה בלי יומן עדיין
נשמרת, רק בלי כתיבה אוטומטית ליומן).

יצירת שיעורים אוטומטית מריצה סוכן חיצוני — `codex` כברירת מחדל, ראו
`src/lib/server/lesson/engine.ts` ו-`LESSON_ENGINE`. ההרשאה שלו היא קובץ
(`$CODEX_HOME/auth.json`, נוצר ע"י `codex login`) ולא משתנה סביבה; פרטי
ההתקנה בשרת נמצאים ב-`server/README.md`.

```bash
npm run build   # vite build — פלט ל-build/, מריץ עם adapter-node
npm run check   # svelte-check — בדיקת טיפוסים
npm test        # node --test על tests/**/*.test.mjs — כולל מבחני האפיון שמריצים build/index.js, אז יש להריץ build קודם
```

להרצה בענן: [`server/README.md`](server/README.md) (Docker Compose + Caddy).
