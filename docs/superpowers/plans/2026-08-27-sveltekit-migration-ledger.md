## Rulings

Ruling P1: the `test` script is `node --test "tests/**/*.test.mjs"`, not `node --test tests/characterization/` — the planned form is broken on Node 22.22, proven above. Cost if wrong: none; the glob is verified working and the quotes keep the shell from expanding it.

Ruling P2: modules under `src/lib/server/` read `process.env` directly, never `$env/dynamic/private`. SvelteKit permits this server-side, and it is what lets `node --test` import them without Vite. Applies to Tasks 7, 9, 10, 12, 21. Cost if wrong: gives up SvelteKit's env-validation ergonomics; a mechanical swap to reverse.

Ruling P3: `startServer` returns `{ baseUrl, stop, dbPath, dataDir }`. The code in the plan already does; only the interface line was short. Cost if wrong: none.

Ruling P4: the `target` function argument is the single mechanism; the harness defaults it from `process.env.TARGET` so `TARGET=sveltekit npm test` works without editing call sites. Supersedes Task 13's "add a TARGET env switch". Cost if wrong: none, it satisfies both call styles.

Ruling P5: Task 6 also moves `images/` → `static/images/` (git mv) and creates `static/`. Without it the favicon 404s from Task 6 and the Task 22 `COPY` fails outright. Cost if wrong: images served from a different path; caught immediately by click-through.

Ruling P6: Task 12 also moves `games/data/*.json` → `$DATA_DIR/games-data/`, and `docker-compose.yml`'s existing `./games/data` mount is retired in Task 22. Deferring this to Task 22 would leave Task 12's route reading an empty directory and its tests passing vacuously. Cost if wrong: generated game data unreachable until the move; caught by the Task 24 click-through.

Ruling P7: `db.ts` honors `DB_PATH` when set, else derives `join(DATA_DIR, 'results.db')`. Keeps the existing deployment's `DB_PATH` working and keeps the harness explicit. Cost if wrong: a deploy could point at an unexpected DB file; the boot check logs the resolved path.
